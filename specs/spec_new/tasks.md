# 实施计划

> **产品愿景**：教育版多邻国 - 让学习像游戏一样上瘾
> 
> **开发范式**：Vibe Coding - 利用 AI 辅助编程加速开发
> 
> **核心约束**：
> - 大模型能力统一使用 `backend/app/services/llm.py`
> - 移动端优先设计
> - 游戏化体验是核心，不是附加

---

## 产品架构回顾

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  错题银行   │ --> │ 认知健身房  │ --> │  AI 学伴   │
│ (冷启动)   │     │  (留存)     │     │  (付费)    │
└─────────────┘     └─────────────┘     └─────────────┘
```

---

## 阶段一：错题银行 MVP 【优先级: P0】

> 目标：让用户能拍照上传错题，体验"错题变资产"的核心价值

### [1]. 数据模型设计 ⏱️ 预估 3h

- 在 `backend/app/models.py` 中新增：
  - `ErrorBankItem` - 错题银行条目
  - `DiagnosisResult` - 错因诊断结果
  - `StudentStats` - 学生统计数据
- 在 `frontend/src/types/` 中同步 TypeScript 类型
- 需求: 1, 5

### [2]. 错题 OCR 识别服务 ⏱️ 预估 4h

- 创建 `backend/app/services/error_ocr.py`
- **复用 `llm.py` 中的 `get_qwen_client()`**
- 实现图片上传 + Qwen-VL 识别
- 解析返回的题目内容、学科、知识点
- 需求: 1

### [3]. 错因诊断服务 ⏱️ 预估 4h

- 创建 `backend/app/services/diagnosis.py`
- **复用 `llm.py` 中的 `_get_client()` 和 `_parse_json_payload()`**
- 实现错因诊断 Prompt
- 实现错题价值计算算法
- 需求: 1

### [4]. 错题银行 API ⏱️ 预估 3h

- 在 `backend/app/main.py` 中新增 `/error-bank/*` 路由
- 实现：上传、列表、详情、状态更新接口
- 实现：统计数据接口（总积分、待修复数等）
- 需求: 1

### [5]. 错题银行前端页面 ⏱️ 预估 6h

- 创建 `frontend/src/pages/ErrorBank/`
- 实现拍照上传组件（移动端优先）
- 实现错题列表页（卡片式展示）
- 实现错题详情页
- 实现首页统计卡片（积分、连续天数、待修复数）
- 需求: 1

**阶段一产出**：用户可以拍照上传错题，看到错因诊断和价值积分

## 阶段二：认知健身房 MVP 【优先级: P0】

> 目标：让用户体验多邻国式的每日训练

### [6]. 变式题生成服务 ⏱️ 预估 5h

- 创建 `backend/app/services/variant_generator.py`
- **复用 `llm.py` 中的 Qwen 调用封装**
- 实现变式题生成 Prompt
- 实现答案自动生成
- 需求: 2

### [7]. 训练生成算法 ⏱️ 预估 4h

- 创建 `backend/app/services/training_generator.py`
- 实现每日训练生成逻辑：
  - 热身（3 题）+ 核心（5 题）+ 挑战（1 题）
- 实现错题优先级排序（顽固 > 高价值 > 长时间未练）
- 需求: 2

### [8]. 训练会话 API ⏱️ 预估 3h

- 新增 `/training/*` 路由组
- 实现：获取今日训练、开始训练、提交答案、完成训练
- 实现生命值机制（答错扣命）
- 需求: 2

### [9]. 训练前端页面 ⏱️ 预估 8h

- 创建 `frontend/src/pages/Training/`
- 实现训练入口页（今日训练卡片）
- 实现训练进行中页面：
  - 生命值指示器（❤️）
  - 进度条
  - 计时器
  - 题目卡片
- 实现答题反馈动画（正确/错误）
- 实现训练结果页
- 需求: 2

### [10]. 游戏化组件 ⏱️ 预估 4h

- 创建 `frontend/src/components/Gamification/`
- 实现连续天数显示
- 实现积分获得动画
- 实现错因修复进度条
- 实现成就解锁动画
- 需求: 2, 5

**阶段二产出**：用户可以每天做 15 分钟训练，体验多邻国式的游戏化学习

## MVP 快速验证路径

若需快速验证核心价值主张，建议优先完成：

```
最小可行产品 (MVP) = 阶段一 + 阶段二（部分）
                   = 任务 1-5 + 6-9
                   ≈ 40h（Vibe Coding 约 20h）
```

MVP 包含：
- ✅ 拍照上传错题
- ✅ AI 错因诊断 + 价值积分
- ✅ 每日 15 分钟训练
- ✅ 生命值 + 进度条 + 答题反馈

**核心用户路径**：
```
拍一道错题 → 看到诊断和积分 → 开始今日训练 → 消灭错题获得积分 → 明天继续
```

## 风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 错题 OCR 识别率低 | 用户体验差 | 支持手动编辑、多次重拍 |
| 变式题质量不稳定 | 训练效果差 | 题目质量评分 + 用户反馈 |
| 游戏化机制不吸引人 | 留存低 | A/B 测试不同激励方案 |
| 小原对话不自然 | 用户不买账 | 持续优化 Prompt + 收集反馈 |
| 移动端体验差 | 用户流失 | 移动端优先开发 + 真机测试 |
